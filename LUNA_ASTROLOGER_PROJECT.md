## 📌 1. Обзор проекта и концепция

**LUNA** — это персональный Telegram Mini App и экосистема астрологических разборов нового поколения с глубоким психологическим, бережным и современным подходом.

### Ключевой манифест продукта:
1. **Никакой категоричности и фатализма:** Астрология подается как инструмент самопознания, психоэмоциональной опоры и поиска ресурсов, а не «роковой судьбы».
2. **Без инфобизнесового пафоса и клише:** Тёплый, глубокий, человечный и эстетичный язык.
3. **Строгое разделение FREE (бесплатного) и PRO (глубоких разборов):**
   - **FREE:** Экспресс-карта дня, Базовая Mini-Натальная карта («Большая Тройка»: ☀️ Солнце, 🌙 Луна, 💫 Асцендент), недельный лунный прогноз, 1 вводный вопрос ИИ-астрологу.
   - **PRO:** Многостраничные фундаментальные книги-разборы (12–14 глав), сгенерированные на основе точных астрономических координат и персональной анкеты жизненного контекста.

## 🏗 2. Архитектура и стек технологий

### 2.1. Frontend (Telegram Mini App)
- **Файл:** `index.html` (Single File WebApp / SPA без тяжелых сборщиков, максимальная скорость и автономность).
- **Стек:** Vanilla HTML5, CSS3 (космическая темная тема, стеклянный нейморфизм Glassmorphism, CSS-анимация звездного неба `stars-overlay`), чистый JavaScript ES6+.
- **Интеграция:** Telegram WebApp SDK (`Telegram.WebApp.ready()`, `expand()`, `HapticFeedback`).
- **Хранилище:** `localStorage` с изоляцией по `telegram_user_id`. Поддерживает профиль пользователя + массив добавленных детей (`children[]`).
- **Хостинг / Деплой:** GitHub Pages (`https://nadinnchik.github.io/luna-app/`), репозиторий `nadinnchik/luna-app`.

### 2.2. Telegram Bot & Backend
- **Директория:** `luna-bot/`
- **Файлы:**
  - `runner_stable.py` / `runner_active.py` — Telegram Long Polling бот.
  - `astro_calc.py` — локальный математический расчет планет (эфемериды/упрощенный расчет координат Солнца, Луны, Асцендента, домов).
  - `set_menu_button.py` / `set_bot_info.py` — настройка WebApp Menu Button и команд.

## 📝 5. Анкетирование перед платным разбором (Context Gate)

Перед генерацией PRO-разбора у пользователя запрашивается контекст (чтобы разбор не был абстрактным «гороскопом из журнала»):
1. **Текущий статус / Ситуация:** (В браке / В поиске / В кризисе / В найме / Развиваю свой проект).
2. **Главный запрос / Боль:** Что беспокоит прямо сейчас.
3. **Для Детской карты:** Выбор ребенка (имя, дата рождения) из профиля.

## 🔒 6. Ключевые правила и логика (Business Logic Checklist)

1. **Zero-Fallback & Empty State:**
   - Если пользователь не ввел данные рождения, приложение не подставляет выдуманные заглушки.
   - Персональные карточки блокируются с призывом ввести данные.
2. **Профиль и дети (`children[]`):**
   - Возможность добавить несколько детей.
   - При открытии детского разбора — выбор, для кого формируется карта.
3. **Безопасность и тональность:**
   - Никаких пугающих прогнозов, болезней, смертей или безапелляционных оценок.
   - Фокус на силе человека, свободе выбора и осознанности.
